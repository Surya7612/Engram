# Engram V2 — Thin Agent Router

V2 runs a **minimum** agent organization around the V1 preflight packet.

Not included: specialist swarm, learned capability routing (V3), merge/deploy.

## What it adds

Three roles only:

| Role | Job | Constraint |
|---|---|---|
| **Manager** | Proposes steps and who should execute | Cannot drop required review or override ADRs/policy |
| **Backend** | Edits a git worktree of the service fixture | Cannot merge, push, or write fixture `main` |
| **Reviewer** | Read-only critique vs evidence | Cannot implement, merge, or approve |

Engram instantiates only as much of that org as risk justifies (`docs`/`allow` → backend only).

## Run

```bash
source .venv/bin/activate
python main.py run \
  --service "Auth Service" \
  --task "Increase auth session TTL from 24 hours to 7 days"
```

Docs path (no reviewer):

```bash
python main.py run \
  --service "Email Service" \
  --task "Fix a typo in the password-reset email copy"
```

API: `POST /run`

## Honest bar

- Candidate lives in a **git worktree** under `.engram/sandboxes/` on branch `engram/<id>`.
  - Sample Auth/Email: cut from fixture repos in `.engram/repos/`.
  - BYO GitHub: shallow clone into `.engram/clones/<owner-name>/`, then worktree (requires network once).
- Fixture/clone **main** is never mutated. Nothing is merged or pushed.
- BYO runs without ADRs/incidents will not look like the Auth TTL block demo—that still needs the sample org.
- Gate is **Engram policy** from V1 preflight, then V2.5 may escalate a constraint violation to `block`.
- The reviewer reports conflicts; it does not get a merge vote.
- With `OPENAI_API_KEY`, roles may use `gpt-4o-mini`. Without it, deterministic stubs run so tests stay offline.
- Naive manager fallback proposes backend-only; Engram adds the reviewer on review/block paths. That override is the V2 point.

```bash
# sample risk demo

# after ingest-github, run on a clone
python main.py run --service "Claude Cookbooks" --task "Add a short Engram worktree note"
```
