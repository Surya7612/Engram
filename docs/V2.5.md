# Engram V2.5 — Risk Router

V2.5 maps **blast radius + policy constraints** to a verification path. Rules only. Not a learned router (V3).

**Live demo:** Auth TTL task on [Try](https://engram-cjph.onrender.com/try) should **block** on ADR-12.

## What it adds

After V2 produces a sandbox candidate and a read-only review, Engram decides the gate:

| Signal | Path |
|---|---|
| Docs / allow | Backend only; gate `allow` |
| Warn or wide deps | Backend + reviewer |
| Auth / payment / high-criticality | Manager + backend + reviewer; human required |
| Candidate or task exceeds an ADR cap (e.g. 168h vs ADR-12 48h) | Gate `block`; human required |

The reviewer still cannot approve. A policy violation is a **block**, not a polite `review`.

## Run

```bash
python main.py run
python main.py run --json   # full packet
```

Default CLI output is a compact summary. API `POST /run` still returns the full result, now including `human_required` and `risk`.

## Honest bar

- Caps are regex-parsed from ADRs that mention TTL/session/cache (`max TTL of N hours`, `at most N hours`). Identity-lifetime ADRs are not treated as session TTL caps.
- No merge, no human inbox product.
